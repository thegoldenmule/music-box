# Parent Admin (superseded draft)

**Status:** active

## Body
Where a parent sets things up and reads what happened. Behind a passcode or Face ID. Needs to be usable in the five minutes a parent actually has, not a configuration project.

## Screens

- **Kids.** Add a kid, give them a name and an age, pick their mode. One kid is the common case; more than one should not feel like an afterthought.
- **Mode.** Three choices, described in plain language with an honest statement of what each does and doesn't catch. The level 2 description in particular must not overpromise — explicit tagging is about lyrics, not themes.
- **Allow list.** Search the real catalog, tap to add. Artists, albums, playlists, songs. Grouped by type so it stays readable when it grows past twenty entries.
- **Deny list.** Same search, opposite effect. Artists and albums only — denying individual songs is busywork when the point is "not this band."
- **Preview.** The most valuable screen and the easiest to skip. Show the parent exactly what their kid's home screen and search results look like under the current settings. Without this, a parent has no way to know whether they've built something usable.
- **Reports.** See Activity Log and Reports (superseded draft).

## Making list building not miserable

Level 1 only works if a parent can build a decent allow list in a sitting. Straight search-and-tap gets tedious fast. Ideas worth trying:

- Suggest starting points by age — a handful of curated artists and playlists we've vetted, as a first-run shortcut.
- Approve from the report. If the kid searched for something and got blocked, put an "allow this" button right there. Over a couple of weeks the list builds itself from the kid's actual interests, which is a much better list than one built cold.
- Bulk approve an artist's back catalog, with a checkbox to also cover future releases.
- Let the parent add the whole thing and then remove exceptions, rather than only adding one at a time.

## The lock

A passcode set on first run, separate from the device passcode, because the kid usually knows the device passcode. Face ID or Touch ID as a convenience on top. If we go Kids Category this also has to be a proper parental gate, which means an adult-level task rather than just a PIN, plus voiceover prompts for pre-readers.

Assume the passcode gets shoulder-surfed eventually. It's a speed bump, not a security boundary, and the design shouldn't depend on it holding forever.
